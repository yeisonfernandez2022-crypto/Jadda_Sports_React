### HU-023 — Cancelar un pedido antes de su envío
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | HU-023 |
| **Título** | Cancelar un pedido antes de su envío |
| **Módulo** | Pedidos |
| **Prioridad** | Media |
| **Estado** | Implementada |
| **RF asociados** | RF-023 |

* **Historia:** Como comprador arrepentido, **quiero** anular un pedido que acabo de realizar antes de que sea despachado, **para** que se libere el stock y, si el pago ya estaba confirmado, se apruebe automáticamente el reembolso de los productos y del costo de envío sin pasar por el administrador.
* **Criterios de aceptación:**
    * **CA-023.1 — Cancelación del cliente con reembolso automático:**
        * **Dado que** deseo cancelar una compra propia que aún no salió del almacén (`ENVIOS.ESTADO_ENVIO` distinto de `EN_CAMINO`/`ENTREGADO`),
        * **cuando** la venta está en `COMPLETADA`, `CONFIRMADA`, `PENDIENTE` o `PENDIENTE_PAGO`,
        * **entonces** el backend la marca `CANCELADA` con `CANCELADA_POR = 'CLIENTE'`, reingresa el stock de cada variante (`ENTRADA` en `MOVIMIENTOS_STOCK`) y cancela el envío.
        * **Además**, si el pago estaba confirmado, crea en `DEVOLUCIONES` una fila `TIPO = 'REEMBOLSO'`, `ESTADO = 'APROBADA'` por producto (agregando variantes repetidas), con el valor de `DETALLE_VENTAS.SUBTOTAL` más `ENVIOS.COSTO_ENVIO`; no se requiere aprobación del admin. Si el envío ya había salido solo se reembolsan los productos; si no se registró ningún cobro, no se crea reembolso.
    * **CA-023.2 — Restricción de anulación en tránsito:**
        * **Dado que** el paquete de mi pedido ya salió del centro de distribución,
        * **cuando** su estado logístico es `EN_CAMINO` o `ENTREGADO`,
        * **entonces** el sistema me prohíbe cancelar de forma autónoma y devuelve el mensaje: "El pedido ya salió del almacén y no puede cancelarse".
        * **Nota:** el admin o el vendedor pueden marcar la venta como `CANCELADA` por gestión, pero en ese caso no se genera reembolso automático.
    * **CA-023.3 — Cancelación por la tienda o el vendedor:**
        * **Dado que** un administrador o el vendedor cancela una venta pagada que no había sido despachada,
        * **cuando** se ejecuta `PUT /api/admin/compras/:id/estado` o `PUT /api/vendedor/ventas/:id/estado` con estado `CANCELADA`,
        * **entonces** la venta queda `CANCELADA` con `CANCELADA_POR = 'TIENDA'`, se aprueba automáticamente el reembolso de los productos y del envío (si no había sido despachado) y el cliente recibe la notificación con el monto; la UI muestra "Cancelada por la tienda".
