### HU-050 — Conversarme por chat con soporte o con el vendedor
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | HU-050 |
| **Título** | Chat multi-canal |
| **Módulo** | Comunicación / Soporte |
| **Prioridad** | Media |
| **Estado** | Implementada |
| **RF asociados** | RF-050 |

* **Historia:** Como usuario de la tienda, **quiero** conversar por chat con el equipo JADDA o con el vendedor de un producto, **para** resolver dudas de envío, disponibilidad y detalles sin salir de la plataforma.
* **Criterios de aceptación:**
    * **CA-050.1 — Accesos al chat:** Desde el **botón flotante** inferior derecha (como el carrito, `FloatingChat` con badge) y desde un producto con **Enviar mensaje** bajo el vendedor (abre el widget con `chat {producto} - {usuario|vendedor}` y foto). Cada producto tiene su chat aparte (`CHAT.ID_PRODUCTO`).
    * **CA-050.2 — Idempotencia por producto:** Al abrir el chat del mismo producto con la misma contraparte se reutiliza la conversación activa (`VENDEDOR` + `ID_CLIENTE` + `ID_VENDEDOR` + `ID_PRODUCTO`).
    * **CA-050.3 — Mensajería:** Envío mensajes (máx. 2000) y veo burbujas; sistema centrado. Polling 4s hilo /12s lista. Funciona para JADDA (`ID_VENDEDOR NULL` -> atiende admin) y vendedores.
    * **CA-050.4 — Censura:** Groserías como palabras completas se censuran (`puta`→`****`, `cabrón`->`******` insensible a tildes/`ñ`), `reputación` queda intacta.
    * **CA-050.5 — Badge de no leídos:** El botón flotante muestra contador rojo (`GET /no-leidos`, polling 12s) por rol, sin leer solo si `LEIDO=0` y `ROL_AUTOR<>miRol`.
    * **CA-050.6 — Admin responde:** Admins ven todos los hilos en su **botón flotante** (cada uno sus chats aparte, sin ruta `/admin/chats`) y responden; no pueden abrir tickets propios de soporte.
