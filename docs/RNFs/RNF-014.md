### Requisitos:

* **RNF-014.1 — Auto-creación de esquema:**
    * Al arrancar, `backend/database/setup.js` debe crear la base y las 33 tablas con `CREATE TABLE IF NOT EXISTS` y sembrar los datos de referencia con `INSERT IGNORE` (idempotente en cada reinicio).
* **RNF-014.2 — Migraciones idempotentes:**
    * Las columnas/tablas/índices nuevos en BD existentes deben aplicarse automáticamente al arrancar (`MIGRACIONES` en setup.js: `ENVIOS.COSTO_ENVIO`, `DESCUENTOS.USADO`, `RETO_EVIDENCIAS`, `NOTIFICACIONES`, `AVISOS_STOCK`, `DEVOLUCIONES`, índice único `uq_categoria_nombre`), verificando `INFORMATION_SCHEMA` antes de cada ALTER.
* **RNF-014.3 — Esquema SQL único para BD nuevas:**
    * `backend/database/schema.sql` (generado con `exportarSchema.js` desde setup.js, fuente única: 33 tablas + seeds con rutas de imágenes locales) debe ser importable en MySQL Workbench para crear la BD desde cero.
* **RNF-014.4 — Volumen nombrado:**
    * Los datos de MySQL deben persistir en el volumen nombrado de Docker `mysql_data` (no en carpeta del repo), garantizando portabilidad entre clones.

### Estado

✅ Implementado: `CREATE IF NOT EXISTS` + migraciones idempotentes + `schema.sql` regenerable (ejecutar `node backend/database/exportarSchema.js` tras cada cambio de esquema) + volumen nombrado.
