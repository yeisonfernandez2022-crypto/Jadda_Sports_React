## MÓDULO 12: TOLERANCIA A FALLOS EN CORREO ELECTRÓNICO (RNF-012)

### Identificación:

| Campo | Valor |
| :--- | :--- |
| **ID** | RNF-012 |
| **Nombre** | No-bloqueo por fallos de correo |
| **Categoría** | Resiliencia |
| **Prioridad** | Alta |
| **Estado** | Implementado |

### Requisitos:

* **RNF-012.1 — El email nunca rompe el flujo principal:**
    * Los envíos de correo (confirmación de pedido con factura adjunta, notificaciones de estado, avisos de stock, devoluciones) deben ejecutarse con try/catch: si el SMTP falla, la operación principal (compra, cambio de estado, aprobación) debe completarse igualmente y el error solo loguearse.
* **RNF-012.2 — Envíos asíncronos no bloqueantes:**
    * Las notificaciones por email/celular para el admin no deben bloquear la respuesta HTTP al cliente.
* **RNF-012.3 — Imágenes locales en correos:**
    * Las rutas relativas de imágenes (`/images/productos/...`) deben resolverse a URLs absolutas (`FRONTEND_URL`) en las plantillas de correo para que el cliente pueda verlas (helper `imagenParaCorreo` en `utils/correo.js`).

### Estado

✅ Implementado end-to-end: checkout (factura adjunta), notificaciones de estado de pedido, avisos de reposición y códigos de verificación capturan errores; los fallos SMTP se prueban vía `docker logs` y no afectan la transacción.
