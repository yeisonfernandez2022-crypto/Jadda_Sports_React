## MÓDULO 13: Sube fotos sin enredos (RNF-013)

### Identificación:

| Campo | Valor |
| :--- | :--- |
| **ID** | RNF-013 |
| **Nombre** | Sube fotos sin enredos |
| **Categoría** | Infraestructura |
| **Prioridad** | Media |
| **Estado** | Implementado |

### Requisitos:

* **RNF-013.1 — Límites de tamaño:**
    * Las subidas por JSON base64 deben tener límites explícitos: imágenes de productos `25mb` (ruta + body-parser global), foto de perfil `10mb`, evidencias de retos `10mb`.
* **RNF-013.2 — Almacenamiento en volumen Docker:**
    * Los archivos subidos deben persistirse vía bind-mount entre el backend (`backend/uploads/...`) y el frontend público (`frontend/public/images/...`) para servirse con URL estática `/images/...`:
    * Productos → `./frontend/public/images/productos:/app/uploads`
    * Fototperfil → `./frontend/public/images/perfiles:/app/uploads/perfiles`
    * Retos → `./frontend/public/images/retos:/app/uploads/retos`
* **RNF-013.3 — Nombres de archivo únicos:**
    * Los archivos subidos usan nombre con timestamp+aleatorio (`<ts>-<rand>.<ext>`) o carpeta por usuario (`u{ID_USUARIO}`) para evitar colisiones.
* **RNF-013.4 — Formatos y directorios pre-creados:**
    * Se aceptan `jpg/png/webp/gif`; los directorios de salida se crean automáticamente (mkdir recursivo).

### Estado

✅ Implementado: los tres flujos (productos, perfil, retos) funcionan SOLO en Docker por los bind-mounts; fuera de Docker no existe la ruta de destino.
