### Requisitos:

* **RNF-006.1 — Comunicación basada en APIs REST:**
    * Todos los servicios internos y el traspaso de información con los clientes web/móviles deben usar estándares de comunicación síncronos bajo el patrón arquitectónico REST utilizando payloads formateados en JSON.
* **RNF-006.2 — Integración fluida con servicios externos:**
    * El backend debe contar con pasarelas de conexión robustas para integrarse ágilmente con proveedores y APIs de terceros (ej. pasarelas de pago, servicios postales logísticos o proveedores de OAuth).
* **RNF-006.3 — Consistencia transaccional ACID:**
    * El sistema debe garantizar estrictamente la consistencia y la atomicidad de los datos en todas las operaciones financieras o de inventario, asegurando que ante una interrupción física no se pierda información en los procesos críticos del negocio.
* **RNF-006.4 — Registro de logs operativos:**
    * El backend debe escribir de forma permanente archivos de bitácora (`logs`) detallados que registren las operaciones importantes de los servicios técnicos para facilitar el rastreo de errores.
* **RNF-006.5 — Trazabilidad y auditoría de administración:**
    * El sistema debe auditar y dejar constancia histórica de las acciones y modificaciones críticas ejecutadas tanto por usuarios regulares como por administradores del backoffice (ej. cambios de precios, modificaciones de stock).
* **RNF-006.6 — Monitoreo en tiempo real:**
    * La infraestructura del servidor de base de datos y de la API debe estar conectada a herramientas de telemetría y monitoreo en tiempo real para evaluar el consumo de memoria, CPU y concurrencia.
* **RNF-006.7 — Alertas ante eventos críticos:**
    * El sistema debe despachar alertas automáticas e inmediatas al equipo de ingeniería (vía Slack, correo o Webhooks) al detectar excepciones imprevistas o eventos críticos de infraestructura.
* **RNF-006.8 — Velocidad en el despacho de notificaciones:**
    * Las notificaciones automáticas originadas por cambios de estado en los pedidos deben enviarse por correo electrónico al cliente en un tiempo menor a 1 minuto desde que ocurre el evento en el sistema.
* **RNF-006.9 — Mecanismo de reintento para correos fallidos:**
    * El microservicio o worker encargado de las notificaciones por correo electrónico debe poseer un sistema de colas automatizado para reintentar el envío de un mensaje en caso de detectar caídas temporales en la comunicación con el servidor SMTP.
