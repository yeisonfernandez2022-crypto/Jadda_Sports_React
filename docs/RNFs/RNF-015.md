## MÓDULO 15: CONTROL DE ACCESO BASADO EN ROLES (RNF-015)

### Identificación:

| Campo | Valor |
| :--- | :--- |
| **ID** | RNF-015 |
| **Nombre** | RBAC (Roles) |
| **Categoría** | Seguridad |
| **Prioridad** | Alta |
| **Estado** | Implementado |

### Requisitos:

* **RNF-015.1 — Dos roles operativos:**
    * El sistema distingue `ID_ROL = 1` (Administrador) y `ID_ROL = 4` (Cliente), almacenados en `USUARIOS.ID_ROL`; el admin se siembra en cada arranque (`seedAdminUser`, credenciales de `.env`).
* **RNF-015.2 — Protección de rutas por middleware:**
    * `esAdmin` (verifica sesión + `ID_ROL === 1`) debe aplicarse a:
        * todo el router `/api/admin/*` (compras del sitio, reportes, usuarios, facturas),
        * CRUD de productos, categorías, características, variantes e imágenes,
        * evidencias de retos (`/api/retos/admin/*`) y devoluciones admin.
    * `verificarSesion` debe proteger las rutas de cliente (carrito, direcciones, compras, favoritos, planes, retos, notificaciones, métodos de pago).
* **RNF-015.3 — `deserializeUser` con rol:**
    * La sesión de Passport debe restaurar también `ID_ROL` para que los guards del frontend (`/admin`) y `esAdmin` funcionen tras refrescar.
* **RNF-015.4 — Respuesta 403 consistente:** Usuarios logueados sin rol admin que llamen a rutas admin reciben `{ ok: false, msg: "No autorizado" }` (401 solo si no hay sesión).

### Estado

✅ Implementado completo: `middlewares/esAdmin`, `deserializeUser` con `ID_ROL`, guards de rutas admin y panel `/admin` en frontend.
