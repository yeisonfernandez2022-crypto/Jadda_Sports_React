## MÓDULO 7: Bien documentada y ordenada (RNF-007)

### Identificación:

| Campo | Valor |
| :--- | :--- |
| **ID** | RNF-007 |
| **Nombre** | Bien documentada y ordenada |
| **Categoría** | Mantenibilidad |
| **Prioridad** | Media |
| **Estado** | Implementado |

### Requisitos:

* **RNF-007.1 — Documentación de requerimientos:**
    * Todos los requerimientos funcionales (RF), historias de usuario (HU) y no funcionales (RNF) deben documentarse en la carpeta `docs/` con el formato establecido.
* **RNF-007.2 — Documentación de API:**
    * Los endpoints deben documentarse en los README de backend/frontend con método, ruta y descripción.
* **RNF-007.3 — README por módulo:**
    * Cada módulo del proyecto (backend, frontend, movil) debe tener su propio README con instrucciones de inicio rápido, stack y variables de entorno.
* **RNF-007.4 — Código limpio:**
    * El código debe seguir convenciones consistentes de nombres, indentación y estructura dentro de cada archivo.
* **RNF-007.5 — Sin comentarios redundantes:**
    * El código no debe contener comentarios explicativos obvios; la claridad debe lograrse mediante nombres descriptivos de variables y funciones.
* **RNF-007.6 — Versionado semántico:**
    * Los commits deben ser descriptivos y atómicos. No se permite subir credenciales, `.env` ni archivos de configuración locales.
