### RF-061 — Gestión de PQR (Peticiones, Quejas y Reclamos)
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-061 |
| **Nombre** | Gestión de PQR |
| **Módulo** | Soporte / PQR |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** El usuario autenticado puede radicar una PQR desde `/pqr` indicando tipo (PETICIÓN/QUEJA/RECLAMO/SUGERENCIA), asunto, descripción y opcionalmente número de pedido. Se guarda en `PQR` con `ESTADO PENDIENTE` y `FECHA NOW()`. El equipo de soporte lo ve en base de datos y da seguimiento.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `tipo` | Enum | Sí | PETICIÓN, QUEJA, RECLAMO, SUGERENCIA |
| `asunto` | Texto | Sí | 5-255 caracteres |
| `descripcion` | Texto | Sí | 10-2000 caracteres |
| `numero_pedido` | Texto | No | 8 dígitos si se envía |

* **Proceso:**
    1. Frontend valida y envía `POST /api/pqr` con `verificarSesion`.
    2. Backend valida `TIPO` y longitudes, inserta en `PQR (ID_USUARIO, TIPO, ASUNTO, DESCRIPCION, NUMERO_PEDIDO, FECHA, ESTADO PENDIENTE)`.
    3. Responde `201` y muestra confirmación; el admin puede consultar directo en BD o futuro panel.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| PQR creada | 201 | `{ ok, id_pqr }` |
| No autenticado | 401 | "No autorizado" |
| Campos inválidos | 400 | Detalle por campo |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/pqr` | Sí | Crea PQR |

* **Reglas de negocio:**
    * **RN-065:** Solo usuarios autenticados pueden radicar PQR; el `NUMERO_PEDIDO` es opcional y no se valida contra ventas existentes (puede ser consulta general).
