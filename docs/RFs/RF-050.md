### RF-050 — Sistema de chat entre usuarios, vendedores y administración
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-050 |
| **Nombre** | Chat multi-canal del marketplace |
| **Módulo** | Comunicación / Soporte |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** Chat por producto con widget flotante inferior derecha (como el carrito). Tres tipos: SOPORTE (usuario↔admins), VENDEDOR (usuario↔vendedor o JADDA para cualquier producto, 1 hilo por `ID_PRODUCTO`: `chat {producto} - {usuario|vendedor}` con foto) y DEVOLUCIÓN (a demanda, `chat devolucion {producto} - {usuario|vendedor}` solo cuando alguien pulsa **Abrir chat**). Cada chat registra `ID_PRODUCTO`, autor, rol, mensaje y `LEIDO`. Censura insensible a tildes/`ñ` (`cabrón`→`******`, `reputación` intacta) en `groserias.js`. Badge en botón flotante por rol.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `tipo` | Enum | Sí | SOPORTE \| VENDEDOR \| DEVOLUCION |
| `id_producto` / `id_devolucion` | Entero | Según tipo | VENDEDOR: cualquier `PRODUCTOS.ID` (JADDA con `ID_VENDEDOR NULL` va a admin); DEVOLUCION: solicitud propia |
| `mensaje` | Texto | Sí (envío) | Máximo 2000; censura insensible a tildes |

* **Proceso:**
    1. En `ProductDetailPage` botón **Enviar mensaje** bajo el vendedor llama `POST /api/chat/iniciar {tipo:VENDEDOR, id_producto}` (idempotente por `ID_CLIENTE+ID_VENDEDOR+ID_PRODUCTO`) y abre el widget flotante con foto del producto.
    2. `GET /api/chat/conversaciones` lista por rol (cada uno sus chats aparte: cliente `ID_CLIENTE=yo`, vendedor `ID_VENDEDOR=suID`, admin ve todo) con `PRODUCTO_NOMBRE/IMAGEN` y `NO_LEIDOS`; el widget filtra a `VENDEDOR`/`DEVOLUCION` y muestra `no hay chats` si vacío.
    3. `GET /api/chat/:id/mensajes` valida `PARTE` y marca leídos del otro bando.
    4. `POST /api/chat/:id/mensajes` guarda censurado, actualiza `ULTIMA_ACTIVIDAD` y notifica al otro bando (JADDA si `ID_VENDEDOR IS NULL` va a admins).
    5. `GET /api/chat/no-leidos` para badge del flotante (polling 12s).
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Chat creado/recuperado | 201/200 | `{ ok, id_chat }` |
| Mensaje enviado | 201 | Mensaje con autor y fecha |
| Sin participación | 403 | `{ ok: false, msg }` |
| Admin abre soporte propio | 400 | "El equipo JADDA es el soporte…" |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/chat/iniciar` | Sí | Inicia o recupera conversación por producto (`VENDEDOR` con `ID_PRODUCTO`) |
| GET | `/api/chat/conversaciones` | Sí | Lista mis conversaciones (por rol, con producto) |
| GET | `/api/chat/no-leidos` | Sí | Total sin leer para badge flotante |
| GET | `/api/chat/:id/mensajes` | Sí | Mensajes del hilo (con `PRODUCTO`) |
| POST | `/api/chat/:id/mensajes` | Sí | Enviar mensaje (censurado, notifica al otro) |
| POST | `/api/chat/:id/escalar` | Participante | Escalar devolución (ver RF-051) |
