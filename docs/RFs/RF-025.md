### RF-025 — Enviar notificaciones del estado y envío del pedido mediante correo electrónico
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-025 |
| **Nombre** | Enviar notificaciones del estado y envío del pedido mediante correo electrónico |
| **Módulo** | Notificaciones |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Mayo 2026 |

* **Descripción:** Envía correos informativos automáticos al cliente cada vez que los operadores modifiquen el estado de su pedido o el estado logístico de su envío. Además crea una notificación in-app (campana) apuntando a `/perfil/compras`. Implementado en `utils/estadoPedido.js` (`notificarCambioEstado`).
* **Entradas:** Evento interno del sistema disparado por cambios en `VENTAS.ESTADO` o `ENVIOS.ESTADO_ENVIO`.
* **Proceso:**
    1. Cuando una orden cambia de estado — `PUT /api/admin/compras/:id/estado` o `PUT /api/admin/compras/:id/envio` — o el cliente la cancela (`POST /api/compras/:id/cancelar`), el backend ejecuta `notificarCambioEstado(idVenta, tipo, estadoNuevo)`.
    2. El helper consulta venta + cliente (EMAIL, NOMBRE_USUARIO), crea la notificación in-app (`NOTIFICACIONES`, tipo `pedido`, ruta `/perfil/compras`) y envía el correo con mensajes por estado ("en camino a tu dirección", "fue entregado", "fue cancelado", etc.).
    3. El envío es asíncrono y nunca bloquea al admin: cualquier error de correo (p. ej. SMTP no alcanzable) se captura y solo se loguea.
* **Salidas:** Operación y ejecución interna del servidor de correos + fila en `NOTIFICACIONES` para el cliente.

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| PUT | `/api/admin/compras/:id/estado` | Admin (`esAdmin`) | Cambia `VENTAS.ESTADO` y dispara email + notificación |
| PUT | `/api/admin/compras/:id/envio` | Admin (`esAdmin`) | Cambia `ENVIOS.ESTADO_ENVIO` y dispara email + notificación |
| POST | `/api/compras/:id/cancelar` | Sesión (cliente) | Cancela el pedido y notifica la cancelación |
