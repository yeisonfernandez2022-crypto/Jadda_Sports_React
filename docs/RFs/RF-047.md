### RF-047 — Suscribirse al boletín de noticias (Newsletter)
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-047 |
| **Nombre** | Newsletter |
| **Módulo** | Mercadotecnia |
| **Prioridad** | Baja |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** Permite a cualquier visitante (logueado o no) suscribir su correo al boletín desde el input del footer. La suscripción se persiste en `backend/data/newsletter.json` (compartido también en el flujo de newsletter del usuario). Cada cierto tiempo (por defecto cada 72 horas, configurable con `NEWSLETTER_INTERVAL_HORAS`) el backend envía correos a toda la lista: un mensaje aleatorio (4 plantillas: ofertas, marca, novedades, entrenamiento) junto con **6 ofertas reales de la BD** (productos con `ID_DESCUENTO` activo, con imagen, precio tachado, precio con descuento y chip `-X%`), enlace al catálogo con descuentos y botón de **desuscripción** en el pie. El administrador puede disparar un envío manual y ver la lista de suscritos + historial desde el backend.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `email` | Texto (Body) | Sí | Formato de correo válido; no duplicado (+1 a la lista) |

* **Proceso:**
    1. El usuario ingresa su email en el Footer y envía `POST /api/newsletter`.
    2. El backend lee/agrega el correo en `backend/data/newsletter.json` (el directorio se crea automáticamente con `mkdirSync recursive`).
    3. Responde éxito; duplicados se ignoran.
    4. Un `setInterval` en `server.js` (cada `NEWSLETTER_INTERVAL_HORAS`, default 72 h) consulta las ofertas activas en `PRODUCTOS`/`DESCUENTOS`, arma el correo con una plantilla aleatoria y lo envía a **todos** los suscritos; los errores SMTP se capturan correo por correo (nunca rompen el lote ni el servidor).
    5. El correo incluye un enlace de desuscripción (`GET /api/newsletter/desuscribir?email=...`) que elimina el correo de la lista y muestra una página de confirmación.
    6. El estado de los envíos se persiste en `backend/data/newsletter-estado.json` (último envío y total acumulado).
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Suscripción guardada | 200/201 | `{ ok: true, mensaje }` |
| Email inválido | 400 | Mensaje descriptivo |
| Desuscripción (POST) | 200 | `{ ok: true, msg }` |
| Desuscripción (link GET) | 200 | Página HTML de confirmación |
| Lista de suscritos (admin) | 200 | `{ ok, lista, total, estado }` |
| Envío manual (admin) | 200 | `{ ok, enviados, suscritos, tema }` |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/newsletter` | No | Registra el correo en la lista de Newsletter |
| POST | `/api/newsletter/desuscribir` | No | Quita un correo de la lista (body `email`) |
| GET | `/api/newsletter/desuscribir?email=` | No | Desuscribe por link del correo y muestra confirmación |
| GET | `/api/newsletter/suscritos` | Sí (admin) | Lista de suscritos + historial de envíos |
| POST | `/api/newsletter/enviar` | Sí (admin) | Envía el newsletter ahora a toda la lista |
