### RF-056 — Solicitud para ser vendedor
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-056 |
| **Nombre** | Solicitud para ser vendedor |
| **Módulo** | Marketplace / Vendedores |
| **Prioridad** | Alta |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** Cualquier visitante (con o sin sesión) puede postularse como vendedor desde `/ser-vendedor`. El formulario recoge representante, empresa/NIT opcionales (vendedor informal), contacto, ubicación y categorías. Si ya existe una solicitud `PENDIENTE` o `APROBADA` para ese usuario/NIT/email, se rechaza. Una solicitud `RECHAZADA` permite reenvío (actualiza a `PENDIENTE`). Al enviar, se crea `SOLICITUDES_VENDEDOR` y se notifica al solicitante.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `nombre_representante` | Texto | Sí | 3-100 caracteres |
| `nombre_empresa` | Texto | No | 3-150 si se envía; NULL si informal |
| `nit` | Texto | No | 5-20 dígitos si se envía; UNIQUE |
| `email_empresa` | Texto | Sí | Formato email, UNIQUE |
| `telefono` | Texto | Sí | 7-15 dígitos |
| `departamento` / `ciudad` | Texto | Sí | De lista 33 departamentos |
| `categorias` | Texto | No | CSV de categorías existentes |

* **Proceso:**
    1. `POST /api/vendedor/solicitud` valida campos y duplicados (`NIT`/`EMAIL` en `VENDEDORES` y `SOLICITUDES_VENDEDOR PENDIENTE/APROBADA`).
    2. Si el solicitante tiene sesión y ya posee solicitud `RECHAZADA`, hace `UPDATE` a `PENDIENTE`; si no, `INSERT` con `ESTADO PENDIENTE`.
    3. Sin sesión (`ID_USUARIO NULL`) crea la solicitud anónima vinculada al email.
    4. Responde `201` con la solicitud; el admin la ve en `/admin/vendedores`.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Solicitud creada | 201 | `{ ok, solicitud }` |
| Ya tienes solicitud en revisión/aprobada | 400 | "Ya tienes una solicitud en revisión" |
| NIT o email duplicado | 409 | "NIT/email ya registrado" |
| Campos inválidos | 400 | Detalle por campo |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/vendedor/solicitud` | No (rate 10/15min) | Crea o reenvía solicitud |
| GET | `/api/vendedor/solicitud` | Sí | Mi solicitud y estado del vendedor |

* **Reglas de negocio:**
    * **RN-056:** `NOMBRE_EMPRESA` y `NIT` permiten `NULL` (vendedor informal) — `SOLICITUDES_VENDEDOR.NIT` y `VENDEDORES.NIT` son `DEFAULT NULL` con `UNIQUE` (múltiples NULL no colisionan).
    * **RN-057:** `RECHAZADA` habilita reenvío; `PENDIENTE`/`APROBADA` lo bloquea.
