### RF-023 — Cancelar un pedido antes de su envío
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-023 |
| **Nombre** | Cancelar un pedido antes de su envío |
| **Módulo** | Pedidos |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Mayo 2026 |

* **Descripción:** Permite al cliente anular un pedido y arrancar de forma automatizada las gestiones de reembolso siempre que el paquete no haya salido del almacén.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `order_id` | Entero (Path) | Sí | ID del pedido que se pretende cancelar |

* **Proceso:**
    1. El usuario solicita la anulación desde su panel de compras.
    2. El backend evalúa el estado del pedido en la base de datos. Si el estado es `paid` o `payment_pending`, aprueba la solicitud; si figura como `shipped`, la rechaza.
    3. Al aprobarse, cambia el estado a `cancelled`, devuelve las unidades reservadas al inventario disponible y lanza la orden de reintegro económico a la API del procesador de pagos.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Cancelación aceptada | 200 | Mensaje: `"Order cancelled successfully, refund initiated"` |
| Pedido ya en tránsito | 400 | Mensaje de error: `"Order cannot be cancelled because it has already been shipped"` |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/compras/:id/cancelar`| Sí | Cancela la orden de compra y libera el stock |

* **Reglas de negocio:**
    * **RN-010:** Ningún pedido cuyo estado logístico figure como enviado (`shipped`) puede ser cancelado de forma autónoma por el usuario.
