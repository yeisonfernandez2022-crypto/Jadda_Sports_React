### RF-023 — Cancelar un pedido antes de su envío
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-023 |
| **Nombre** | Cancelar un pedido antes de su envío |
| **Módulo** | Pedidos |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Mayo 2026 (completado 2026-08-13) |

* **Descripción:** Permite al cliente anular un pedido siempre que el paquete no haya salido del almacén. El backend cambia los estados, devuelve el stock de los productos comprados (registrando `ENTRADA` en `MOVIMIENTOS_STOCK`) y notifica al cliente. El reembolso económico se gestiona de forma semi-manual: el pedido cancelado muestra el botón "Solicitar reembolso", que crea las solicitudes en `DEVOLUCIONES` (motivo "Reembolso por cancelación del pedido") para que el admin las apruebe desde `/admin/devoluciones` (no hay pasarela de pagos real).
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `order_id` | Entero (Path) | Sí | ID del pedido que se pretende cancelar |

* **Proceso:**
    1. El usuario solicita la anulación desde su panel de compras (`POST /api/compras/:id/cancelar`).
    2. El backend evalúa el estado del pedido (`VENTAS.ESTADO`). Solo los estados `COMPLETADA` o `PENDIENTE` son cancelables; si el envío ya salió (`EN_CAMINO`/`ENTREGADO`) o el pedido está en otro estado, se rechaza.
    3. Al aprobarse, **dentro de una transacción**: devuelve el stock de cada variante comprada (`PRODUCTO_VARIANTES.STOCK + CANTIDAD`), registra `ENTRADA` en `MOVIMIENTOS_STOCK`, marca `ESTADO = CANCELADA` y `ESTADO_ENVIO = CANCELADO`; el rollback revierte todo si algo falla.
    4. Dispara `notificarCambioEstado` (email + campana in-app) tras el commit, sin bloquear la operación.
    5. El pedido cancelado permite al usuario solicitar reembolso (`POST /api/compras/:id/reembolso`), que crea las `DEVOLUCIONES` por producto; el admin las aprueba/rechaza en `/admin/devoluciones`.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Cancelación aceptada | 200 | Mensaje: `"Compra cancelada"` |
| Pedido no cancelable | 400 | Mensaje: `"Esta compra ya no se puede cancelar"` |
| Envío ya salió del almacén | 400 | Mensaje: `"El pedido ya salió del almacén y no puede cancelarse"` |
| Pedido inexistente / ajeno | 404 | Mensaje de compra no encontrada |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/compras/:id/cancelar`| Sí | Cancela la orden de compra y notifica al cliente |

* **Reglas de negocio:**
    * **RN-010:** Ningún pedido cuyo estado logístico figure como enviado (`EN_CAMINO`, `ENTREGADO`) puede ser cancelado de forma autónoma por el usuario (verificado en el backend contra `ENVIOS.ESTADO_ENVIO`).
    * **Reembolso:** semi-manual vía `DEVOLUCIONES` + aprobación admin (botón "Solicitar reembolso" en el pedido cancelado); no hay pasarela de pagos real.
    * **Stock:** al cancelar se libera el stock de las variantes compradas y se registra en `MOVIMIENTOS_STOCK` (nota: ventas creadas antes del 2026-08-13 nunca decrementaron stock en checkout, por lo que su cancelación reingresa unidades que no se habían descontado).
