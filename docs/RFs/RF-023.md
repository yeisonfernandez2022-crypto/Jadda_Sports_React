### RF-023 — Cancelar un pedido antes de su envío
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-023 |
| **Nombre** | Cancelar un pedido antes de su envío |
| **Módulo** | Pedidos |
| **Prioridad** | Media |
| **Estado** | Implementado parcialmente |
| **Fecha** | Mayo 2026 |

* **Descripción:** Permite al cliente anular un pedido siempre que el paquete no haya salido del almacén. El backend cambia los estados y notifica al cliente; el reembolso económico y la devolución de stock NO están implementados.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `order_id` | Entero (Path) | Sí | ID del pedido que se pretende cancelar |

* **Proceso:**
    1. El usuario solicita la anulación desde su panel de compras (`POST /api/compras/:id/cancelar`).
    2. El backend evalúa el estado del pedido (`VENTAS.ESTADO`). Solo los estados `COMPLETADA` o `PENDIENTE` son cancelables; si el envío ya salió, se rechaza.
    3. Al aprobarse, marca `ESTADO = CANCELADA` y `ESTADO_ENVIO = CANCELADO`, y dispara `notificarCambioEstado` (email + campana in-app).
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Cancelación aceptada | 200 | Mensaje: `"Pedido cancelado correctamente"` |
| Pedido no cancelable | 400 | Mensaje: `"El pedido ya no puede cancelarse"` |
| Pedido inexistente / ajeno | 404 | Mensaje de compra no encontrada |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/compras/:id/cancelar`| Sí | Cancela la orden de compra y notifica al cliente |

* **Reglas de negocio:**
    * **RN-010:** Ningún pedido cuyo estado logístico figure como enviado (`ENVIADO`, `EN_CAMINO`, `ENTREGADO`) puede ser cancelado de forma autónoma por el usuario.
    * **Pendiente:** reembolso económico automatizado y liberación de stock.
