### RF-059 — Gestión de productos por el vendedor
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-059 |
| **Nombre** | Gestión de productos del vendedor |
| **Módulo** | Marketplace / Vendedores |
| **Prioridad** | Alta |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** El vendedor gestiona su catálogo en `/vendedor/productos` (solo sus productos). Puede crear con `SubirImagenes` y variantes/ficha, editar (vuelve a `PENDIENTE` para re-aprobación), y eliminar solo si no está `APROBADO`. El público solo ve `APROBADO` o legacy `NULL`; el admin aprueba/rechaza en `/admin/productos` y notifica.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `nombre` | Texto | Sí | 3-150 |
| `precio` | Número | Sí | >0 |
| `imagenes` | Array URL | Sí | ≥1 imagen |
| `variantes` | Array | No | Si hay, cada una con stock ≥0 |

* **Proceso:**
    1. `POST /api/vendedor/productos` inserta `PRODUCTOS` con `ID_VENDEDOR=req.vendedor` y `ESTADO_PUBLICACION PENDIENTE`, inserta `PRODUCTO_IMAGENES`/`PRODUCTO_VARIANTES`/`PRODUCTO_CARACTERISTICAS`.
    2. `PUT /api/vendedor/productos/:id` valida pertenencia (`WHERE ID_VENDEDOR`) y actualiza; si estaba `APROBADO` vuelve a `PENDIENTE` y notifica admin.
    3. `DELETE` bloquea si `APROBADO` (400); si no, borra en cascada.
    4. Público filtra `(ESTADO_PUBLICACION IS NULL OR APROBADO)` en `obtenerProductos`/`obtenerProductoPorId`/`obtenerRelacionados`/`obtenerRecomendados` y checkout.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Creado pendiente | 201 | Producto con `PENDIENTE` |
| Editado y reenviado | 200 | `PENDIENTE` para revisión |
| Eliminar aprobado | 400 | "No puedes eliminar un producto aprobado" |
| No pertenece al vendedor | 404 | "Producto no encontrado" |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| GET | `/api/vendedor/productos` | Sí (vendedor) | Mis productos |
| POST | `/api/vendedor/productos` | Sí (vendedor) | Crear pendiente |
| PUT | `/api/vendedor/productos/:id` | Sí (vendedor) | Editar y reenviar |
| DELETE | `/api/vendedor/productos/:id` | Sí (vendedor) | Eliminar si no aprobado |
| POST | `/api/admin/productos/:id/aprobar` | Sí (admin) | Aprueba y notifica |
| POST | `/api/admin/productos/:id/rechazar` | Sí (admin) | Rechaza con observación |

* **Reglas de negocio:**
    * **RN-061:** `ESTADO_PUBLICACION` `NULL`=Jadda legacy visible, `PENDIENTE`/`RECHAZADO` oculto, `APROBADO` visible.
    * **RN-062:** Editar un `APROBADO` lo devuelve a `PENDIENTE` para nueva revisión del admin.
