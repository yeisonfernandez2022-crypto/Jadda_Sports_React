### RF-057 — Gestión de solicitudes de vendedores (admin)
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-057 |
| **Nombre** | Gestión de solicitudes de vendedores |
| **Módulo** | Administración / Vendedores |
| **Prioridad** | Alta |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** El administrador revisa en `/admin/vendedores` todas las solicitudes (`PENDIENTE` primero) con empresa, solicitante, ubicación y estado. Puede aprobar o rechazar. Al aprobar se crea `USUARIOS` vendedor (`ID_ROL=6`, `DEBE_CAMBIAR_PASSWORD=1`, password temporal de 10 caracteres) y `VENDEDORES`, y se envían credenciales por correo. Al rechazar exige motivo (5-500) y lo notifica por correo y campana.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `id_solicitud` | Entero | Sí | Existe y en `PENDIENTE` |
| `accion` | Enum | Sí | `APROBADA` \| `RECHAZADA` |
| `observacion` | Texto | Si RECHAZADA | 1-500 caracteres, trim no vacío |

* **Proceso:**
    1. `GET /api/vendedor/admin` lista con `LEFT JOIN USUARIOS` (solicitudes sin cuenta muestran “Sin cuenta”).
    2. `POST /api/vendedor/admin/:id/procesar` en transacción `FOR UPDATE`: si ya procesada →400; si `APROBADA` valida email único, genera `USUARIO` `vendedor_<slug>.<4dígitos>`, `INSERT USUARIOS` y `VENDEDORES`, envía correo `plantillaCredenciales` y notificaciones; si `RECHAZADA` exige `observacion` → `UPDATE` y correo `plantillaRechazo`.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Aprobada | 200 | Vendedor creado, correo enviado |
| Rechazada | 200 | Motivo registrado y notificado |
| Sin observación al rechazar | 400 | "Debes indicar el motivo" |
| Ya procesada | 400 | "Esta solicitud ya fue procesada" |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| GET | `/api/vendedor/admin` | Sí (admin) | Lista solicitudes |
| POST | `/api/vendedor/admin/:id/procesar` | Sí (admin) | Aprueba/rechaza |

* **Reglas de negocio:**
    * **RN-058:** Al `APROBAR` el email de empresa no debe existir en `USUARIOS`; el `USUARIO` se genera único y el vendedor debe cambiar password al primer login (`DEBE_CAMBIAR_PASSWORD=1` fuerza Swal).
    * **RN-059:** `RECHAZADA` siempre requiere y persiste `OBSERVACION_ADMIN` visible para el solicitante.
