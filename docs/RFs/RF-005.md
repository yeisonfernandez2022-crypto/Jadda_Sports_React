### RF-005 — Cierre de sesión seguro
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-005 |
| **Nombre** | Cierre de sesión seguro |
| **Módulo** | Autenticación |
| **Prioridad** | Alta |
| **Estado** | Implementado |
| **Fecha** | Mayo 2026 |

* **Descripción:** Garantiza la desconexión del usuario, forzando la expiración e invalidación inmediata del token de acceso JWT actual para mitigar riesgos de secuestro de sesión.
* **Entradas:** Ninguna en el cuerpo del payload (Body). Requiere el token JWT en las cabeceras HTTP de autorización.
* **Proceso:**
    1. El usuario pulsa sobre la opción "Cerrar sesión".
    2. El backend lee el token del encabezado `Authorization: Bearer <token>`.
    3. Calcula el tiempo de vida remanente del JWT y almacena el string del token en una lista negra en memoria caché (ej. Redis).
    4. El cliente elimina los registros de tokens guardados en las variables locales de almacenamiento volátil de la app.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Cierre exitoso | 200 | Mensaje informativo: `"Logout successful"` |
| Petición sin credenciales | 401 | Mensaje de error: `"Signature has expired or token is invalid"` |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/v1/auth/logout` | Sí | Envía el token JWT en uso actual a la lista negra del servidor |

* **Reglas de negocio:**
    * **RN-005:** Cualquier solicitud entrante que presente un token JWT alojado activamente en la lista negra de Redis será rechazada con un código HTTP 401 de manera inmediata.
