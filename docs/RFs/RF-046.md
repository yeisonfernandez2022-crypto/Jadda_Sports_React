### RF-046 — Subir imágenes de productos desde el panel administrador
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-046 |
| **Nombre** | Subida de imágenes (admin) |
| **Módulo** | Panel de administración / Catálogo |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** Permite al Administrador o al Vendedor subir imágenes de productos desde su computador (multi-archivo, base64) o pegar una URL, desde el modal de agregar producto o en `EditarProductoAdmin` (Sidebar). Con `CLOUDINARY_URL` las imágenes van a la carpeta `jadda/productos/{producto-{id}|nuevos}` (folder explícito, `public_id` lo genera Cloudinary; ojo si se usara `public_id` explícito: pasar SOLO el nombre base + folder, nunca ambos completos). Sin Cloudinary (o si falla la subida), fallback a `backend/uploads/subidas/` — con `idProducto` : `Producto_NN/img_{orden}.{ext}` continuando la numeración, sin id: `<ts>-<rand>.{ext}` (bind-mount `frontend/public/images/productos`). El `crearProducto`/`actualizarProducto` las reciben como arreglo `IMAGENES` (URLs con ORDEN secuencial 1..N).
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `imagenes` | Array (Body) | Condicional | Cada imagen: `{ nombre, data }` base64 data URL, máx 8 archivos, **6 MB por archivo** (total base64 ~14 MB; la ruta admite `25mb`) |
| `IMAGENES` | Array de URLs | No | URLs asignadas al producto con ORDEN secuencial |
| `URL_IMAGEN` | Texto | No | Fallback: imagen individual |

* **Proceso:**
    1. `SubirImagenes.tsx` (usado en `AdminProductos` y `EditarProductoAdmin`) lee archivos (jpg/png/webp/gif), genera previews con botón ✕ o acepta URL pegada.
    2. `POST /api/productos/imagenes` valida **magic bytes** con `detectarFormato` (formato real del buffer, rechaza archivos renombrados) y coherencia MIME declarado↔contenido, luego sube a Cloudinary (`jadda/productos/...`, URLs `res.cloudinary.com`) o guarda en disco y devuelve las URLs.
    3. Al guardar el producto, `IMAGENES` se inserta en `PRODUCTO_IMAGENES` con ORDEN 1..n.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Imágenes subidas | 200 | `{ urls: [...] }` |
| Sin archivo/base64 | 400 | Mensaje de error |
| Imagen con bytes no reconocidos o MIME↔extensión incoherente | 400 | Mensaje con nombre del archivo |
| Archivo > 6 MB | 400 | "supera el límite de 6 MB por imagen" |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/productos/imagenes` | Admin o Vendedor (`esAdminOVendedor`) | Sube imágenes base64 (Cloudinary primero, fallback disco) |
| POST/PUT | `/api/productos` `/api/productos/:id` | Admin | Reciben `IMAGENES` (array de URLs) |

* **Nota defuncionamiento:** con `CLOUDINARY_URL` configurada funciona también FUERA de Docker (los binarios son media remota). El fallback a disco vale en Docker (bind-mount `./frontend/public/images/productos:/app/uploads`).
