### RF-054 — Cupones RETO con compra mínima escalada y cupones disponibles
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-054 |
| **Nombre** | Cupones con condiciones |
| **Módulo** | Promociones / Retos |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** El cupón ganado al completar un reto aplica a TODA la compra con compra mínima escalada según su porcentaje (3–4%→$50.000; 5–6%→$100.000; 7–9%→$150.000; ≥10%→$200.000; columna `DESCUENTOS.MONTO_MINIMO`). El checkout rechaza antes de transaccionar si el subtotal no alcanza el mínimo, sin consumir el cupón. El correo/notificación indican las condiciones. En el checkout, el panel "Ver cupones disponibles" muestra promos vigentes de la tienda y los cupones RETO personales (con estado usado/expirado); aplicar uno que no cumpla muestra la condición exacta en vivo hasta superar el mínimo.
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `codigo` | Texto | Sí | Coincidencia EXACTA (TRIM; insensible a mayúsculas) |
| `MONTO_MINIMO` | Decimal | No | ≥ 0 (creación admin) |

* **Proceso:** helper compartido `reglasCupones.js` (backend/frontend) define el mínimo; `generarCupon` lo persiste; `validar` devuelve `monto_minimo`+`fecha_fin`; checkout aplica la regla autoritativa.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Validar bajo mínimo (checkout) | 400 | "El cupón X requiere una compra mínima de $Y (tu carrito suma $Z)" |
| Cupón parcial no existe | 404 | "Cupón no encontrado" |
| Aplicado sobre el mínimo | 200 | Venta con descuento; RETO marcado USADO=1 |

* **Endpoints asociados:**

| Método | Ruta | Auth | Descripción |
| :--- | :--- | :--- | :--- |
| GET | `/api/cupones/disponibles` | Sí | Tienda + personales con condiciones |
| POST | `/api/cupones/validar` | No | Validación exacta |
| POST | `/api/checkout/procesar` | Sí | Aplicación autoritativa |
