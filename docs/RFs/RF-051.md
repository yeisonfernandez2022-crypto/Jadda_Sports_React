### RF-051 — Escalación de disputas de devolución al equipo JADDA
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-051 |
| **Nombre** | Escalación y decisión de disputas |
| **Módulo** | Devoluciones / Comunicación |
| **Prioridad** | Media |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** Las solicitudes sobre productos de vendedores externos se negocian primero entre comprador y vendedor en su chat de acuerdo. Si el vendedor rechaza (o en cualquier momento), cualquiera de las partes puede escalar: el hilo de acuerdo se cierra y se crean DOS hilos separados con JADDA (columna `CHAT.PARTE`: CLIENTE/VENDEDOR), notificando a cada parte y a los administradores. Solo entonces el admin decide (aceptar devolución/reembolso, más pruebas o rechazar); la decisión final cierra todos los hilos con un mensaje del sistema. Si el admin pide más pruebas tras escalar, las nuevas evidencias regresan a él (no al vendedor).
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `decision` | Enum | Sí (vendedor/admin) | devolver \| reembolsar \| mas_pruebas \| rechazar |
| `observacion` | Texto | Según decisión | Obligatoria en rechazo/más pruebas; máx 500 |
| `estado_envio`/`estado` | Enum | Sí (ventas) | Estados válidos de ENVIOS/VENTAS |

* **Proceso:**
    1. `solicitarDevolucion` **no** autocrea chat (evita vacíos); solo notifica al vendedor (`/vendedor/devoluciones`) o al admin si es JADDA. El hilo `chat devolucion {producto} - {usuario|vendedor}` se crea a demanda en `POST /api/chat/iniciar {tipo:DEVOLUCION}` al pulsar **Abrir chat** en el detalle de la devolución.
    2. `POST /api/vendedor/devoluciones/:id/procesar` aplica la decisión del vendedor; solo APROBADA cierra el chat.
    3. `POST /api/chat/:id/escalar` (cliente o vendedor) → `ESCALADA`, cierre del acuerdo, creación de 2 hilos `PARTE` con `ID_PRODUCTO` y **mensaje sistema enriquecido** con todos los datos (pedido, producto, motivo, cliente/vendedor) + notificación a admin con resumen para decidir.
    4. `POST /api/devoluciones/admin/:id/procesar` rechaza con 403 si no es `ESCALADA`; al decidir cierra todos los hilos.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Escalada exitosa | 200 | Hilos CLIENTE y VENDEDOR creados |
| Admin procesa no escalada | 403 | "…solo llega a tu decisión si se escala…" |
| Decisión final | 200 | Estado actualizado + chats cerrados |

* **Endpoints asociados:**

| Método | Ruta | Auth | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/chat/:id/escalar` | Participante | Escalar al equipo JADDA |
| GET | `/api/vendedor/devoluciones` | Vendedor | Solicitudes de sus productos |
| POST | `/api/vendedor/devoluciones/:id/procesar` | Vendedor | Decisión del vendedor |
| POST | `/api/devoluciones/admin/:id/procesar` | Admin | Decisión final JADDA |
