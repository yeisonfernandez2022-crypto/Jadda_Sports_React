### RF-045 — Subir y cambiar la foto de perfil
* **Identificación:**

| Campo | Valor |
| :--- | :--- |
| **ID** | RF-045 |
| **Nombre** | Foto de perfil |
| **Módulo** | Usuario / Perfil |
| **Prioridad** | Baja |
| **Estado** | Implementado |
| **Fecha** | Agosto 2026 |

* **Descripción:** Permite al usuario autenticado subir una foto de perfil desde su computador (base64, límite 10 MB). Con `CLOUDINARY_URL` configurada se sube a la carpeta `jadda/perfiles/{clave}` (backend/utils/cloudinary.js) y se devuelve la URL Cloudinary; si no, o si la subida falla, se guarda en disco en `backend/uploads/usuarios/{clave}/perfil/perfil-{ts}.{ext}` (carpeta por usuario según `utils/carpetaUsuario.js`: clave = USUARIO saneado, fallback `u{ID}`) y queda servida en `/images/usuarios/{clave}/perfil/...`. La URL se persiste con `PUT /api/auth/perfil` (`foto_url`) y se usa en Navbar, dropdown y Perfil (avatar con borde rojo + modal de vista en pantalla completa).
* **Entradas:**

| Campo | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :--- | :--- |
| `imagen` | Base64 (Body) | Sí | ≤ 10 MB (límite de la ruta), imagen válida (jpg/png/webp/gif) |

* **Proceso:**
    1. El usuario hace click en su avatar → menú → "Cargar foto desde el navegador" (input file fuera del menú para que el diálogo abra).
    2. `POST /api/auth/foto` sube la foto (Cloudinary `jadda/perfiles/{clave}` o disco `usuarios/{clave}/perfil/`, borrando la anterior local) y devuelve `{ ok, url }`.
    3. `PUT /api/auth/perfil` con `foto_url` persiste la ruta y `refreshPerfil()` actualiza el contexto.
* **Salidas:**

| Escenario | Código HTTP | Respuesta |
| :--- | :--- | :--- |
| Foto subida | 200 | `{ ok: true, url: "https://res.cloudinary.com/..." o "/images/usuarios/{clave}/perfil/..." }` |
| Imagen demasiado grande | 400 | Mensaje de límite 10 MB |
| Sin sesión | 401 | Mensaje de sesión inactiva |

* **Endpoints asociados:**

| Método | Ruta | Auth requerida | Descripción |
| :--- | :--- | :--- | :--- |
| POST | `/api/auth/foto` | Sí | Sube y guarda la foto de perfil (Cloudinary o disco) |
| PUT | `/api/auth/perfil` | Sí | Persiste `foto_url` en `USUARIOS` |

* **Nota defuncionamiento:** con `CLOUDINARY_URL` configurada funciona también FUERA de Docker (la media vive en Cloudinary); el fallback a disco vale en Docker (bind-mounts). `/images/usuarios` se sirve desde el backend con permisos (perfil público para autenticados; retos y devoluciones solo del dueño/admin).
